P1 · AGENT_HARNESS_ENGINEERING 공식 발표 FAST-MOVING

OpenAI, Codex Harness를 API 한 번으로 여는 “Agents API” 공개 베타 출시

WHAT

2026-09-10 OpenAI가 오픈소스 Codex harness(코딩 에이전트 런타임) 위에 구축한 관리형 API “Agents API”를 공개 베타로 출시했다. 개발자가 직접 구현해야 했던 세션 유지, 오케스트레이션, 컨텍스트 압축, 복구 로직을 OpenAI가 대신 관리한다. 구조는 네 객체로 나뉜다 — Agent(모델, 지시사항, 도구, MCP 서버를 정의), Environment(파일 접근·명령 실행이 실제로 일어나는 샌드박스), Session(작업을 수행하고 입력에 응답하는 지속가능한 에이전트 인스턴스), Events/Items(에이전트로 들어오고 나가는 입출력). 핵심 기능은 네 가지다: 세션이 토큰 한도에 가까워지면 자동으로 이전 컨텍스트를 압축하는 기능, 필요한 시점에만 도구 정의를 불러와 토큰 비용을 줄이고 프롬프트 캐시를 보존하는 Tool Search, 도구 호출을 병렬 실행·체이닝하고 결과를 코드로 필터링해 관련 데이터만 컨텍스트로 반환하는 프로그래매틱 도구 호출, 그리고 메인 에이전트가 작업을 나눠 각자 컨텍스트를 유지한 채 병렬로 처리하는 서브에이전트 기능이다. 같은 날 OpenAI는 이 인프라와는 별개로 금융서비스 특화 제품 “ChatGPT for Financial Services”도 출시했다.

WHY

지금까지 “에이전트 하네스”는 각 팀이 스스로 설계해야 하는 인프라였다 — 컨텍스트가 넘칠 때 무엇을 버리고 무엇을 남길지, 도구 목록이 늘어날 때 프롬프트 캐시를 어떻게 지킬지, 서브에이전트 간 결과를 어떻게 병합할지는 전부 하네스 설계자의 판단 영역이었다. Agents API는 그 판단 로직 자체를 OpenAI가 관리형 서비스로 표준화해 판다는 선언이다. 단순 기능 추가가 아니라 “에이전트 하네스”라는 계층 자체가 하나의 독립 제품 카테고리로 굳어지고 있다는 신호이며, Anthropic Claude Agent SDK나 이 Knowledge Agent가 매일 쓰는 subagent 오케스트레이션과 같은 문제를 상업 API 뒤로 감춘 사례다.

FOR YOU

agent_harness_engineering은 이미 confirmed_known 수준이 높은 도메인이지만, tool_calling_runtime_architecture는 여전히 partial 상태로 남아 있다 — “모델이 보내는 것은 실행이 아니라 구조화된 요청이며, 그 사이에 하네스가 거부·변형·승인을 끼워 넣을 수 있다”는 지점이 residual gap으로 기록돼 있다. Agents API의 네 객체 구조가 정확히 그 지점을 실제 제품으로 구현한 사례다: Agent가 만드는 건 “이 도구를 이렇게 호출하고 싶다”는 요청일 뿐이고, 그 요청이 실제로 파일에 닿고 명령이 실행되는 곳은 별도 계층인 Environment(샌드박스)다. 그 둘 사이에 Session이 앉아 컨텍스트 압축·오케스트레이션이라는 형태로 개입한다 — “모델의 의도”와 “실행”이 물리적으로 다른 계층에, 다른 신뢰 경계 안에 있다는 걸 실물 API 설계로 보여준다. system_design_architecture.development_targets.logical_boundary_vs_runtime_boundary에서 “강제 지점을 계층(아래)으로 낮추는” 방향을 아직 스스로 도출하지 못했다고 기록돼 있는데, 이 Environment가 바로 그 “아래 계층”의 실물 사례다.

LEARN

이 주제는 codex_features/fast_moving 카테고리라 API 세부 스펙(가격, rate limit, SDK 문법)까지 깊게 따라갈 필요는 없다 — 몇 달 안에 또 바뀐다. 다만 “에이전트 하네스가 관리형 서비스로 표준화되는 방향”이라는 구조적 흐름 자체는 evolving_practice로 계속 지켜볼 가치가 있다. ME_HEAD/Knowledge Agent 같은 자체 하네스를 설계할 때, Agent/Environment/Session/Events라는 네 객체 분리를 참고 아키텍처로 삼을 만하다.

OpenAI 공식 발표 원문 보기 → openai.com

3줄 요약

  1. 이 API는 개발자가 컨텍스트 압축, 도구 관리, 세션 유지 로직을 직접 구현하지 않아도 되도록 지원하는 관리형 에이전트 API이다.
  2. 자동 컨텍스트 압축, 필요 시에만 도구를 불러오는 Tool Search, 병렬 도구 호출 및 서브에이전트 처리 등의 기능을 제공한다.
  3. 같은 날 금융서비스 특화 제품인 “ChatGPT for Financial Services”도 별도로 공개되었다.

용어 해설

프롬프트 캐시
모델이 이전에 처리한 프롬프트의 앞부분(시스템 지시문, 도구 정의 등 반복되는 내용)을 재사용해 매번 처음부터 다시 계산하지 않도록 하는 기법. 이번 Tool Search 기능은 도구 정의를 필요할 때만 불러와 이 캐시가 깨지지 않게 유지하는 것이 핵심이다.
P0 · SECURITY 공식 발표 EVOLVING_PRACTICE

Anthropic 위협 정보 보고서 — 생물무기 연구 지원 요청은 막았지만, 경쟁 모델로 우회당했다

WHAT

Anthropic이 2026-09-10, 2025년 12월~2026년 8월 사이 자사 Threat Intelligence 팀이 탐지·차단한 Claude 오용 사례를 7개 영역(사이버 작전, 영향력 작전, 감시, 사기, 생물학적 오용, 재래식 무기 개발, 불법 증류)으로 정리한 보고서를 공개했다. 가장 눈에 띄는 사례는 생물학적 오용 영역이다 — 2026년 5월, 군사 연구기관을 위한 치쿤구니야 바이러스 기능획득(gain-of-function) 연구 보조금 신청서 작성을 돕는 요청이 들어오자 Anthropic의 생물학적 안전 분류기가 이를 차단했다. 요청자는 곧바로 우회 플랫폼을 거쳐 다시 접근을 시도했고, 그 우회 플랫폼에는 Claude가 거부한 프롬프트를 자동으로 경쟁사 모델에 재전송하는 폴백 기능이 내장돼 있었다는 사실이 Anthropic 조사에서 드러났다. 이 밖에 말리 소재 컨설턴트 한 명이 Claude로 자국 정보기관용 SIM카드 약 2,500만 개 모니터링 플랫폼(“Lakana 360”)을 구축한 사례, 중국 정부 연계 행위자가 시리아 내 위구르족 추적·프로파일링에 활용한 사례, 연애 앱 20여 개를 운영하며 AI 페르소나 4,700여 개가 2주간 약 2만5천 명과 236만 건의 메시지를 주고받은 사기 사례(실제 인력과 AI 페르소나를 3:1로 섞고 자동화 사실은 밝히지 말라고 지시), ShinyHunters(GTG-50014)가 APK 파일 150만 개 이상에서 하드코딩된 비밀정보를 스캔한 사이버 작전 사례가 담겼다. 오용에 쓰인 모델은 대부분 Claude Haiku/Sonnet/Opus였고, 최신 세대인 Fable/Mythos는 불법 증류 사건 한 건을 제외하면 등장하지 않았다.

WHY

이 보고서가 가치 있는 건 “AI가 위험하다”는 추상적 경고가 아니라, 실제로 걸러진 요청과 그걸 우회하려던 시도까지 함께 공개했기 때문이다. 안전장치가 서류상 존재한다는 것과 실제로 그 순간에 작동했다는 것은 다른 얘기인데, 이 보고서는 후자의 구체적 증거(생물무기 연구 지원 요청이 실제로 차단됨)를 제시한다. 동시에 그 안전장치의 한계도 같은 사례 안에서 드러난다 — Anthropic의 분류기는 Anthropic 서비스 경계 안에서만 작동하고, 사용자가 그 경계를 벗어나 경쟁사 모델로 가면 그 즉시 무력화된다. “안전장치가 실제로 작동하는가”라는 질문 바로 다음에 “그 작동 범위가 어디까지인가”라는 두 번째 질문이 따라붙는 사례다.

FOR YOU

security 도메인은 현재 overall mid로, 서버단 권한 검증이나 SQL Injection 같은 애플리케이션 계층 기본기는 이미 confirmed_known이지만 “벤더가 모델 위험을 등급화해 배포 조건에 직접 연결한다”는 거버넌스 축은 2026-09-10 브리프(GPT-6 Astra의 Preparedness Framework “Critical” 등급)에서 막 다루기 시작한 참이다. 이번 사례는 그 축에 두 번째 조각을 더한다: GPT-6 Astra 건이 “사전 평가에서 위험 능력을 측정해 배포를 막는다”(배포 전 게이트)를 보여줬다면, 이번 건은 “배포된 뒤에도 실시간으로 요청을 걸러낸다”(런타임 게이트)는 걸 보여주고, 동시에 그 런타임 게이트가 한 회사의 서비스 경계에서 끝난다는 것도 보여준다. 이건 system_design_architecture.development_targets.logical_boundary_vs_runtime_boundary에서 이미 다루는 “강제 지점이 어디에 있어야 실제로 강제되는가”와 정확히 같은 질문의 새 층위다 — 지금까지는 “한 시스템 안에서 강제 지점을 어느 계층에 두는가”였다면, 이번 건은 “그 강제 지점이 여러 벤더로 이뤄진 생태계 전체에서 뚫리지 않으려면 무엇이 더 필요한가”(업계 공동 차단 리스트, 규제 기반 강제 등)라는 상위 질문을 보여준다. AX 강의에서 “기업이 AI 리스크를 판단할 때 벤더 하나의 안전장치만 믿으면 안 되는 이유”를 설명할 구체적 실화 사례로 쓸 수 있다.

LEARN

security는 사용자의 실무·강의 양쪽에 직결되는 P0/P1 우선순위 도메인이라 이 흐름은 계속 따라갈 가치가 있다(evolving_practice) — 다만 이번 건에서 새로 배워야 할 “메커니즘”은 분류기 자체의 기술적 구현이 아니라 위에서 정리한 “단일 벤더 강제의 경계” 개념이다. 개별 위협 그룹(GTG 코드)이나 사건 하나하나를 암기할 필요는 없다.

3줄 요약

  1. Anthropic이 2026년 9월 10일 2025년 12월부터 2026년 8월까지 탐지·차단한 Claude 오용 사례를 7개 위협 영역으로 정리한 Threat Intelligence Report를 공개했다.
  2. 보고서에는 기능획득 생물학 연구 지원 요청 차단, 말리·시리아 관련 감시 플랫폼 구축, 연애 앱을 통한 대규모 사기, ShinyHunters의 APK 비밀정보 스캔 등의 구체 사례가 포함됐다.
  3. 악용된 모델은 대부분 Haiku·Sonnet·Opus였으며, 대다수 작전은 실제 피해 확산 전 단계에서 적발되어 계정 비활성화와 정보 공유 등으로 대응됐다.

용어 해설

gain-of-function
병원체가 감염력·전파력·치명률 등을 더 강하게 갖도록 실험실에서 개량하는 연구(기능획득 연구). 백신·치료제 개발에 쓰이기도 하지만 유출·악용 시 위험한 병원체를 만들 수 있어 안전 논쟁의 대상이다.
생물학적 안전 분류기
모델이 생물무기·병원체 관련 위험 요청인지 자동으로 판별해 차단하는 필터 시스템. 사람이 일일이 검토하지 않아도 위험 신호가 감지되면 즉시 요청을 걸러낸다.
불법 증류
상위 모델의 응답을 대량 수집해 그 지식을 다른(주로 더 작은) 모델에 학습시키는 “모델 증류” 기법을, 이용약관을 어기고 몰래 수행하는 것. 타사 모델을 훈련시키려고 Claude의 출력을 부정 사용하는 행위다.
