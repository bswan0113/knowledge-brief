검문소는 그대로인데, 검문받는 단위가 커졌다

오늘 조사한 것 중 지금 당신에게 학습 가치가 있다고 판단한 것만 남겼습니다. 나머지는 이미 아는 내용이거나 가치가 낮아 걸러냈습니다.

하네스 설계 · 오늘의 핵심 공식 변경 기록 + 타사 문서 빨리 바뀜

Claude Code에 Code Mode가 들어왔다. 도구를 하나씩 부르지 않고 스크립트로 한꺼번에 부른다

WHAT

Claude Code 2.1.323 변경 기록에 Code Mode가 실험 기능으로 추가됐다. 기본값은 꺼짐이고, 사용자가 직접 켜야 한다. 조직 단위로 끄는 방법도 따로 안내한다고 적혀 있다.

Code Mode에서 Claude는 도구를 하나씩 호출하지 않는다. 대신 여러 도구를 부르는 JavaScript를 직접 쓴다. 그 스크립트가 도구들을 차례로, 또는 동시에 호출한다.

이 방식은 Claude Code만의 것이 아니다. 같은 이름의 기능이 이미 여러 곳에 있다.

  • Docker 에이전트: 개별 도구를 감추고 스크립트 실행 도구 하나만 모델에게 보여 준다.
  • Vercel AI SDK: 격리된 JavaScript 엔진에서 스크립트를 돌린다. 역시 실험 기능이다.
  • Codex 하네스: 비슷한 Code Mode를 안정 기능으로 두고 있다고 타사 문서가 언급한다.

단, 변경 기록이 가리키는 Claude Code 안내 문서는 오늘 열리지 않았다(404). 그래서 Claude Code에서 권한 검사가 어떤 단위로 걸리는지는 아직 확인하지 못했다.

WHY

기존 방식은 한 걸음마다 모델을 거친다. 모델이 도구 하나를 부르고, 결과를 읽고, 다음 도구를 고른다. 열 단계짜리 일이면 모델 왕복이 열 번이다.

Code Mode는 이 열 번을 한 번으로 줄인다. Docker와 Vercel 문서가 꼽는 이점은 이렇다.

  • 서로 무관한 호출을 동시에 돌린다.
  • 큰 결과는 스크립트 안에서 걸러 필요한 부분만 모델에게 넘긴다.
  • 반복과 분기를 모델 대신 코드가 처리한다.

대가는 검문 쪽에서 생긴다. Docker 문서는 승인이 스크립트 호출 자체에만 걸린다고 적는다. 스크립트 하나를 승인하면, 평소라면 확인을 묻거나 거부됐을 도구까지 허용한 셈이 된다는 경고도 붙였다.

Vercel은 반대로 막는다. 승인이 필요한 도구를 스크립트 안에서 부르면 실행하지 않고 거부한다. 같은 이름의 기능인데 검문 방식이 정반대다.

FOR YOU

당신은 강제 지점을 고를 때 이미 두 가지를 묻는다. 통제 대상이 그 지점을 고칠 수 있는가. 실제 실행이 그 지점을 반드시 지나가는가.

Code Mode는 세 번째 질문을 꺼낸다. 그 지점은 무엇을 한 단위로 보고 판정하는가.

스크립트 단위 검문은 앞의 두 조건을 다 통과할 수 있다. 모델은 샌드박스를 못 고치고, 모든 호출은 스크립트를 지난다. 그래도 검문이 스크립트 전체를 한 덩어리로 보면, 그 안의 삭제 호출 하나는 따로 심사받지 않는다.

이 모양은 당신에게 낯설지 않다. SQL 인젝션 문항에서 당신은 필터의 위치는 맞는데 그 자리의 규칙이 새는 경우를 따로 떼어 봤다. 이번엔 규칙의 빈틈이 아니라 규칙이 보는 단위가 문제다.

야간 브리프 하네스에도 같은 구조가 이미 있다.

  • 무인 실행은 허용 도구 목록으로 Bash(python *)를 연다.
  • 이 규칙은 명령 문자열의 앞부분만 본다. 파이썬 스크립트가 안에서 무엇을 하든 통과한다.
  • 그래서 실제로 일을 막는 건 허용 목록이 아니라, 그 스크립트가 무엇을 하도록 쓰였느냐다.

AX 강의에서는 "한 번에 알아서 다 해 주면 더 좋은 것 아니냐"는 질문으로 돌아온다. 답은 승인 버튼 한 번이 허락하는 범위가 넓어진다는 것이다. 속도와 검문의 해상도를 맞바꾸는 거래로 설명하면 된다.

LEARN

지금 켜 볼 기능은 아니다. 실험 기능이고 안내 문서도 아직 열리지 않는다. 사실만 알아 두고, 문서가 열리면 세 가지만 확인하면 된다.

  • 승인이 스크립트 단위인가, 안쪽 호출 단위인가.
  • 거부 규칙이 스크립트 안의 호출에도 적용되는가.
  • 스크립트가 중간에 실패하면 이미 실행된 호출은 어떻게 되는가.

3줄 요약

  1. Claude Code 2.1.323은 Claude가 JavaScript로 도구를 호출하는 실험 기능 Code Mode를 추가했고, 기본값은 꺼져 있으며 권한 검사 단위는 미확인이다.
  2. Docker 문서에 따르면 Code Mode는 여러 호출을 한 턴에 묶고 결과를 걸러 토큰을 줄인다.
  3. 다만 Docker는 스크립트 하나의 승인이 막혔어야 할 도구까지 허용할 수 있다고 경고하고, Vercel AI SDK는 승인이 필요한 도구를 스크립트 안에서 거부한다.

왜 지금 이걸 다루나

에이전트의 실행 루프는 단순하다. 행동하고, 결과 신호를 받고, 그 신호를 보고 다음 행동을 고른다. 그래서 에이전트의 판단은 신호의 품질을 넘지 못한다.

지금까지 그 신호는 하네스가 만들었다. 도구가 끝나면 하네스가 결과를 그대로 모델에게 돌려줬다. Code Mode는 이걸 바꾼다. 모델이 쓴 스크립트가 무엇을 돌려줄지 직접 고른다.

무엇이 달라지나

Docker 문서는 이렇게 적는다. 스크립트 안의 중간 결과는 모델에게 가지 않는다. 스크립트가 마지막에 돌려주는 문자열 하나만 간다.

즉 모델이 다음 행동을 고를 근거를 모델 자신이 미리 정해 둔다. 이때 신호가 망가지는 모양은 세 가지다.

  • 삼킨 오류: 스크립트가 예외를 잡고 "완료"만 돌려준다. 모델은 성공으로 읽는다.
  • 버린 증거: 큰 결과를 거르다가 판단에 필요한 줄까지 지운다. 모델은 없는 것으로 읽는다.
  • 되돌아가지 않는 절반: Docker 문서에 따르면 중간에 실패해도 이미 실행된 호출은 되돌리지 않는다. 모델이 처음부터 다시 돌리면 앞 단계가 두 번 실행된다.

FOR YOU

이 원리는 당신이 이미 하네스에 박아 둔 규칙과 같다. 야간 브리프의 실행 규칙에는 "자연어 출력이나 종료 코드 0은 성공 증거가 아니다"라는 문장이 있다. 판정받는 쪽이 스스로 쓴 보고는 약한 증거라는 뜻이다.

Code Mode에서는 이 문제가 모델 안쪽으로 들어온다. 보고를 쓰는 쪽과 그 보고로 다음 행동을 고르는 쪽이 같다. 사람이 봐야 할 곳도 그래서 바뀐다.

  • 반환 문자열이 아니라 스크립트 원문을 읽는다. 예외를 잡는 부분이 무엇을 돌려주는지 본다.
  • 안쪽 호출 하나하나의 기록을 본다. Docker는 화면에 안쪽 호출과 상태를 따로 보여 준다.
  • 재시도 전에 이미 끝난 단계를 확인한다. 두 번 실행돼도 괜찮은 작업인지 먼저 묻는다.

강의에서는 이렇게 바꿔 말할 수 있다. "에이전트가 '다 했어요'라고 하면, 그 말을 누가 썼는지부터 보세요."
