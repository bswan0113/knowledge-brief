토큰 하나가 정확히 무엇을 세는 단위인가

왜 지금 이걸 다루는지

매일 밤 이 브리프에는 “백만 토큰당 3달러” 같은 가격 표시가 계속 나옵니다. 그런데 그 “토큰”이 정확히 무엇을 세는 단위인지는 아직 한 번도 다루지 않았습니다. 이 단위를 모르면 컨텍스트 창 크기, API 비용, 문서 분할 방식이 전부 “어쨌든 큰 숫자”로만 남습니다.

FOR YOU

당신은 이미 컨텍스트 용량과 그것을 활용하는 능력이 서로 다른 변수라는 결론을 스스로 낸 적이 있습니다. 토큰은 바로 그 컨텍스트 용량을 채우는 실제 단위입니다. “1M 컨텍스트”라는 숫자는 글자 수가 아니라 토큰 수의 상한을 가리킵니다.

아래 용어 해설의 서브워드 분할 방식 때문에, 같은 문장도 언어와 기호에 따라 토큰 수가 달라집니다. 이건 당신이 아직 다루지 않은 RAG 문서 분할과 바로 연결됩니다 — 분할 크기는 결국 토큰 수로 정해지기 때문입니다.

당신의 야간 브리프 시스템도 매일 지식 로그와 프로필 파일을 프롬프트에 얹습니다. 그 파일들이 계속 길어지면 토큰 수가 늘어나 컨텍스트 상한에 더 빨리 가까워집니다. “로그를 요약해서 압축한다”는 설계 판단은 사실 토큰 예산을 관리하는 일입니다.

LEARN

  • 토큰 — 모델이 텍스트를 읽고 쓸 때 실제로 다루는 최소 단위입니다.
  • 토큰화 — 원문 텍스트를 이 토큰들로 잘라내는 전처리 단계입니다.
  • 모델 파라미터 vs 컨텍스트 — 파라미터는 학습 때 고정되는 값이고, 컨텍스트는 요청마다 달라지는 입력 토큰 수입니다. 서로 다른 두 숫자입니다.

이 세 가지는 오래 가는 기초라 유행을 타지 않습니다. 한 번 자리 잡으면 다시 설명할 필요가 없는 지식입니다.

3줄 요약

  1. 토큰은 모델이 텍스트를 처리하는 최소 단위이며, 같은 글자 수라도 언어에 따라 토큰 수가 달라진다.
  2. 토큰화는 원문 텍스트를 사전에 등록된 어휘 목록 기준으로 토큰 단위로 쪼개는 전처리 단계다.
  3. “1M 컨텍스트” 표현과 API 가격은 문자 수가 아닌 토큰 수를 기준으로 하며, 모델 파라미터와는 별개의 값이다.
