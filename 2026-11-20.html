Claude Code 2.1.329: Code Mode에서 훅이 오류를 내도 도구 호출이 거부되지 않는다

WHAT

Claude Code 변경 기록에 Code Mode의 훅 처리 변경이 올라왔다. 호출 전에 검사하는 훅이 오류를 내도, Code Mode는 이제 그 도구 호출을 거부하지 않는다.

호출을 막고 싶으면 훅마다 "onFailure": "block"을 직접 적어야 한다. 2.1.328은 이 설정을 MCP 도구 훅에도 추가했다.

Code Mode는 Claude가 JavaScript 스크립트 하나로 여러 도구를 부르는 실험 기능이다. 2.1.329는 텔레메트리나 기능 플래그가 꺼져 있어도 이 기능이 시작되게 했고, 관리자는 관리형 설정으로 끌 수 있다.

WHY

  • 검사를 맡은 훅이 죽으면 검사가 사라진다. 이때 통과시키는 쪽이 기본값이 됐다.
  • 막는 쪽으로 바꾸는 설정은 훅 하나하나에 따로 달아야 한다.
  • 변경 기록의 문구상 이전에는 거부했던 것으로 읽힌다. 기본값을 바꾼 이유는 적혀 있지 않다.
  • 변경 기록에 날짜와 재현 사례는 없다. 실제 사고 보도도 확인하지 못했다.

FOR YOU

당신은 강제 지점의 두 조건을 스스로 정리했다. 통제 대상의 쓰기 권한 밖에 있고, 실제 실행 경로 위에 있어야 한다는 것이다.

오늘 변경은 그 위에 세 번째 질문을 얹는다. 검문소가 고장 났을 때 문이 닫히는가, 열리는가이다.

  • 닫히면 안전하지만 작업이 멈춘다.
  • 열리면 작업은 계속되지만 검사가 사라진다.
  • 어느 쪽이 맞는지는 그 검사가 막는 피해의 크기가 정한다.

당신의 야간 하네스는 이미 닫히는 쪽이다. 영수증 명령이 실패하면 외부 작업을 시작하지 않고 종료한다.

반면 허용 목록에 있는 Bash(python *)는 검사의 단위가 넓다. 훅을 추가할 때는 그 훅이 죽었을 때 어느 쪽으로 열리는지 먼저 적어 두는 편이 좋다.

AX 강의에서는 이렇게 물을 수 있다. “보안 검사 프로그램이 꺼지면 에이전트는 계속 일하나요?”

LEARN

개념은 이미 가졌으니 사실만 알아두면 된다. Code Mode를 쓰거나 훅으로 권한 검사를 하고 있다면, 그 훅에 "onFailure": "block"이 있는지 한 번 확인한다.

에이전트 루프는 누가 “끝났다”고 말하는가

왜 지금 이걸 다루나

오늘 변경에서 검사가 죽어도 루프는 계속 돈다. 그렇다면 루프를 멈추는 쪽의 판단은 무엇을 근거로 하는가를 같이 봐야 한다.

WHAT

에이전트 루프는 한 바퀴가 네 단계다. 모델이 행동을 요청하고, 하네스가 실행하고, 결과를 모델에 돌려주고, 모델이 다음 행동을 정한다.

이 순환이 멈추는 순간은 종료 조건이 정한다. 종료 조건은 보통 네 가지다.

  • 모델이 “완료했다”고 말한다.
  • 정해 둔 최대 횟수나 예산에 도달한다.
  • 검증 통과 같은 외부 증거가 나온다.
  • 사람이 개입한다.

WHY

첫 번째 조건만 있으면 문제가 생긴다. 모델의 “완료”는 주장이지 증거가 아니다.

일부 파일만 고치고도 “전부 수정했다”고 말할 수 있다. 하네스가 그 말을 믿으면 실패한 작업이 완료로 기록된다.

반대로 끝나지 않는 쪽도 있다. 횟수나 예산 상한이 없으면 모델이 계속 시도하는 한 루프는 이어진다.

FOR YOU

당신은 야간 자동화의 영수증 규칙에서 이미 같은 원리를 쓰고 있다. 자연어 출력과 프로세스 종료 코드 0은 성공의 증거가 아니라고 정했다.

그 규칙은 종료 조건의 세 번째 칸을 채운 것이다. 단계가 끝났다는 말 대신 영수증이라는 외부 증거를 요구한다.

지난 11월 13일에는 “12개 파일을 고쳤다”는 보고와 실제 결과가 다를 수 있는 경우를 다뤘다. 그때의 질문을 이번에는 루프의 출구 쪽에서 다시 보는 것이다.

예측해 보자. 모델이 “테스트를 모두 통과했다”고 말하지만 하네스는 테스트를 직접 돌리지 않는다. 이 루프의 종료 조건은 몇 개이고, 그중 증거는 몇 개인가?

답은 이렇다. 조건은 사실상 하나이고, 증거는 0개다. 오늘 훅 이야기와 합치면, 검사 하나가 죽어도 루프를 계속 돌리는 하네스는 출구도 말뿐일 때 가장 위험하다.

LEARN

종료 조건마다 “말인가, 증거인가”를 표시해 보는 연습이 가장 빠르다. 횟수와 예산 상한은 증거가 아니라 안전장치로 따로 센다.

3줄 요약

  1. 에이전트 실행 루프는 모델이 행동을 요청하면 하네스가 실행하고, 결과를 모델에 돌려준 뒤 모델이 다음 행동을 정하는 순환이다.
  2. 루프의 종료는 모델의 ‘완료’ 선언, 최대 횟수 도달, 검증 통과, 사람의 개입 중 종료 조건이 정한다.
  3. 모델의 ‘완료’는 증거가 아닌 주장이라 하네스의 별도 검증이 필요하며, 최대 횟수와 예산 상한이 없으면 루프가 끝나지 않을 수 있다.

용어 해설

종료 조건
에이전트가 작업을 끝내도 되는 기준을 미리 정한 조건이다. 이 조건이 없으면 루프가 언제 멈출지 정해지지 않는다.
스텝 예산
한 작업에서 허용하는 최대 반복 횟수나 도구 호출 수의 상한이다. 넘으면 멈추거나 사람에게 넘긴다.
검증 게이트
다음 단계로 넘어가기 전에 결과가 통과해야 하는 검사 지점이다. 통과하지 못하면 수정 단계로 되돌린다.
