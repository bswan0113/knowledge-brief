공식 이름이 붙은 패키지도 설치만으로 열쇠를 가져가고, 그 열쇠가 얼마나 위험한지는 권한 범위가 정한다

오늘 조사한 것 중 지금 당신에게 학습 가치가 있다고 판단한 것만 남겼습니다. 나머지는 이미 아는 내용이거나 가치가 낮아 걸러냈습니다.

보안 · 오늘의 핵심 기술매체 계속 바뀌는 중

Microsoft 공식 에이전트 프레임워크 패키지가 뚫려, 설치한 PC의 클라우드 열쇠를 빼갔다

WHAT

11월 17일 Microsoft의 파이썬 Agent Framework 패키지에 악성 버전 두 개가 올라왔다. 버전은 1.26.1과 1.26.2다. 이 패키지의 월 다운로드는 약 20만이다.

악성 버전은 정상 부품을 그대로 달고 있어서 프레임워크는 평소처럼 동작했다. 뒤에서는 파이썬이 켜질 때 비밀을 훔치는 코드가 돌았다. 패키지를 불러오지 않아도 실행됐다.

훔치려 한 것은 다음과 같다.

  • 환경변수, 설정 파일, 실행 중인 프로세스에 든 Azure·AWS·GitHub·Docker·Hugging Face·OpenAI 비밀
  • Azure 관리형 ID 토큰과 Azure DevOps 인증 토큰
  • 1.26.2에서 추가된 GitHub Actions 인증 토큰

모은 데이터는 공격자가 만든 수신 주소 하나로 전송됐다.

WHY

PyPI는 첫 버전을 격리했다. 그런데 약 2.5분 뒤 두 번째 버전이 또 올라왔다. 공격자가 격리 뒤에도 게시 권한을 쥐고 있었다는 뜻이다.

침투 경로는 아직 모른다. BleepingComputer가 Microsoft에 물었지만 기사 시점까지 답이 없었다. 실제로 몇 곳이 털렸는지, 전송이 끝까지 성공했는지도 확인되지 않았다. Socket, StepSecurity, Ox Security가 분석한 내용이 근거다.

FOR YOU

어제 다룬 Kokoro 건에서는 신원의 근거가 남의 손에 넘어갔다. 오늘 건은 그 근거가 “공식 이름”이었다. 이름이 맞아도 그 이름으로 올라오는 파일이 안전하다는 보증은 없다.

당신은 9월에 위험 문자열을 걸러내는 방식을 스스로 기각했다. 이름을 믿는 방식도 같은 종류다. 이름이 아니라 설치가 무엇을 실행할 수 있는지로 판단해야 한다.

오늘 밤 확인할 것은 세 가지다.

  • 11월 17일 이후 agent-framework를 설치한 환경이 있는지 본다. 1.26.1이나 1.26.2면 감염으로 취급한다.
  • 감염이 의심되면 그 환경에서 읽을 수 있던 키와 토큰을 전부 교체한다.
  • 야간 브리프 실행 환경에 CI 토큰이나 클라우드 키가 환경변수로 들어 있는지 훑는다.

AX 강의라면 이런 질문이 된다. 수강생 PC에서 파이썬 패키지 설치는 누가 승인하는가.

LEARN

사실만 알아 두면 충분하다. 다만 의존성 버전 고정과 해시 검증은 이번 같은 사고에서 가장 먼저 효과가 있는 습관이라 따로 익혀 둘 만하다.

3줄 요약

  1. 2026년 11월 17일 PyPI에 Microsoft Agent Framework 패키지의 악성 버전 1.26.1·1.26.2가 올라왔고, 패키지를 불러오지 않아도 실행됐다.
  2. Azure·AWS·GitHub 등의 비밀정보와 토큰이 수집돼 외부 주소로 전송됐으며, 두 번째 버전은 첫 버전 격리 약 2.5분 뒤 게시됐다.
  3. 권고는 1.26.0으로 환경을 깨끗이 재구축하고, 접근 가능했던 자격증명을 교체하며, 송신 로그를 확인하는 것이다.

용어 해설

.pth 파일
파이썬이 시작할 때 경로를 등록하려고 읽는 설정 파일이다. 한 줄이 import로 시작하면 그 코드가 바로 실행된다.

PyPI가 의심스러운 릴리스를 검토가 끝날 때까지 설치 대상에서 빼 두는 상태다.
OIDC 토큰
CI 작업이 장기 비밀번호 없이 자기 신원을 클라우드에 증명하는 단기 토큰이다.
Azure 관리형 ID
Azure 리소스에 자동으로 붙는 신원이다. 코드에 자격증명을 넣지 않고 Azure 서비스에 접근하게 해 준다.

로그인이 맞아도 권한이 넓으면 사고는 커진다: 인증과 인가를 토큰에서 다시 보기

WHY

위 사고에서 훔친 것은 비밀번호가 아니라 토큰이다. 토큰이 새면 “누구냐”는 질문은 통과한다. 남는 질문은 “그 신원이 무엇을 할 수 있느냐”다.

WHAT

인증은 신원을 확인하는 단계다. 인가는 그 신원에게 허용할 동작을 정하는 단계다. 두 단계는 서로 따로 실패한다.

  • 인증이 뚫리면 남이 내 이름으로 들어온다.
  • 인증이 멀쩡해도 권한이 넓으면 정당한 신원이 너무 많은 일을 할 수 있다.
  • 베어러 토큰은 가진 사람 누구에게나 통한다. 유출은 곧 인증 통과다.

그래서 토큰이 새는 사고의 크기는 두 값으로 정해진다. 하나는 권한 범위이고 다른 하나는 유효 시간이다.

FOR YOU

당신은 화면에서 버튼을 숨기는 것을 권한으로 치지 않는다. 서버에서 검증해야 한다는 걸 바로 판단한다. 토큰도 같은 눈으로 보면 된다.

서버가 매 요청에서 던져야 할 질문은 둘이다.

  • 이 토큰이 유효한가.
  • 이 토큰의 권한이 지금 요청한 동작을 포함하는가.

야간 브리프의 카카오 연동이 이 원리를 쓴다. 접근 토큰은 6시간이면 만료되고 갱신 토큰은 약 60일이다. 자주 쓰이는 열쇠를 짧게 만들어 새도 오래 못 쓰게 한 구조다.

예측 과제 하나. 야간 실행에 쓰는 1년짜리 토큰이 새면 공격자는 무엇을 할 수 있는가. 그 답이 곧 그 토큰의 권한 범위다. 한 번 확인해 볼 만하다.

LEARN

이 주제는 오래 가는 기초다. 토큰을 발급할 때마다 범위와 만료를 먼저 적는 습관이 오늘 건 같은 사고에서 피해 크기를 줄인다.

3줄 요약

  1. 인증은 “당신이 누구인가”를 확인하고, 인가는 “그 신원이 무엇을 할 수 있는가”를 정한다.
  2. 두 단계는 따로 실패하며, 신원이 맞아도 권한이 넓으면 사고가 커지고, 베어러 토큰은 가진 사람 누구에게나 통한다.
  3. 토큰이 유출되면 인증은 통과하고 피해 크기는 권한 범위와 유효 시간이 정하며, 대응은 권한 최소화·짧은 만료·즉시 폐기다.

용어 해설

베어러 토큰
토큰을 들고 있는 쪽이 곧 권한 보유자로 인정되는 토큰이다. 소지 자체가 인증이 된다.
스코프
토큰이 허용하는 작업 범위를 적은 목록이다. 예를 들어 read:orders처럼 쓰고, 서버는 이 값으로 기능별 접근을 제한한다.

ID 토큰은 로그인한 사용자의 신원을 알려 준다. 액세스 토큰은 API 호출 권한을 담고, API 서버가 검사하는 쪽이다.
