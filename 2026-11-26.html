응답 코드 첫 자리는 누구 잘못인지 알려주는 표지판이다

오늘 조사한 것 중 지금 당신에게 학습 가치가 있다고 판단한 것만 남겼습니다. 나머지는 이미 아는 내용이거나 가치가 낮아 걸러냈습니다.

API 연동 · 강의에 바로 쓸 것 개념 설명 오래 가는 기초

404가 두 번 나온 뒤 성공한 이유와 400이 계속 난 이유

왜 지금 이걸 다루나

당신의 야간 배포 확인에는 이미 이 주제가 들어 있습니다. 주소가 404나 503을 몇 번 내다가 나중에 오늘 내용을 보여준 날이 여러 번 있었습니다. 반대로 카카오 전송은 링크 항목을 빠뜨리자 400으로 계속 실패했습니다.

둘 다 "실패"로 보이지만 숫자가 말하는 내용은 정반대입니다. 수강생도 같은 자리에서 막힙니다. "오류 났는데 다시 하면 되나요?"라는 질문입니다.

핵심 구분

응답 코드는 세 자리 숫자이고 첫 자리만 읽어도 절반은 풀립니다.

  • 2로 시작: 서버가 요청을 처리했습니다.
  • 4로 시작: 요청 자체가 틀렸습니다. 그대로 다시 보내면 같은 답이 옵니다.
  • 5로 시작: 서버 쪽 사정입니다. 잠시 뒤에는 될 수 있습니다.

그래서 카카오 400은 재시도가 아니라 요청 수정이 답이었습니다. 반면 503이 한 번 나온 뒤 성공한 것은 서버가 잠깐 바빴다는 뜻입니다.

숫자만 믿으면 틀리는 두 경우

  • 404는 보통 "없다"이지만, 배포 직후에는 "아직 없다"일 수 있습니다. 상황을 함께 봐야 합니다.
  • 200은 처리됐다는 뜻이지 내용이 맞다는 보증이 아닙니다. 오류 없이 엉뚱한 내용을 주는 사고도 실제로 있습니다.

요청 방식이 재시도 가능 여부를 정한다

읽기 요청은 반복해도 안전합니다. 상태를 바꾸는 요청은 다릅니다. 메시지 전송이 대표적입니다.

응답을 못 받았다고 같은 전송을 다시 보내면 두 통이 갈 수 있습니다. 같은 요청을 몇 번 보내도 결과가 같은 성질을 멱등성이라 부릅니다. 읽기는 대체로 멱등하고 전송은 보통 아닙니다.

FOR YOU

당신의 영수증 규칙은 이 구분을 이미 코드로 갖고 있습니다. 카카오 전송 뒤 응답이 오지 않으면 모름으로 두고 다시 보내지 않습니다. 전송이 멱등하지 않기 때문입니다.

반대로 배포 주소 확인은 읽기라서 간격을 두고 여러 번 물어도 아무 문제가 없습니다. 같은 "다시 시도"라도 두 동작의 안전도가 다릅니다.

실패를 만나면 이 순서로 물어보면 됩니다.

  • 첫 자리는 4인가 5인가?
  • 이 요청은 읽기인가, 상태를 바꾸는가?
  • 바꾸는 요청이면, 이미 처리됐는지 먼저 확인할 수 있는가?

강의에서는 이렇게 답할 수 있습니다. "4로 시작하면 요청을 고치고, 5로 시작하면 기다렸다 다시 시도합니다. 상태를 바꾸는 요청은 확인하고 보냅니다."

LEARN

용어는 이미 일부 알고 계시니, 코드 숫자를 외우기보다 첫 자리와 요청 방식 두 가지를 입에 붙이는 쪽이 낫습니다. 오래 가는 기초라 낡을 일이 거의 없습니다.

예측 과제 하나입니다. 결제 요청을 보냈는데 응답 없이 시간이 초과됐습니다. 곧바로 같은 요청을 다시 보내도 될까요? 답은 아니오이고, 먼저 결제가 처리됐는지 확인해야 합니다.

3줄 요약

  1. 200번대는 처리 성공, 400번대는 요청 자체가 틀려 고쳐서 보내야 하며, 500번대는 서버 사정이라 잠시 뒤 재시도하면 될 수 있다.
  2. 같은 404라도 배포 직후에는 아직 없다는 뜻일 수 있고, 200이 와도 내용이 맞다는 보증은 아니다.
  3. 읽기 요청은 반복해도 안전하지만 메시지 전송처럼 상태를 바꾸는 요청은 확인 없이 재전송하면 중복이 생길 수 있다.

용어 해설

멱등성
같은 요청을 여러 번 보내도 결과가 한 번 보낸 것과 같은 성질입니다. 이 성질이 있어야 응답을 못 받았을 때 안심하고 다시 보낼 수 있습니다.
4xx와 5xx
4로 시작하는 코드는 요청에 문제가 있다는 클라이언트 오류이고, 5로 시작하는 코드는 요청은 적절했지만 서버가 실패했다는 서버 오류입니다.
