OWASP 2026 LLM Top 10 — "Excessive Agency"가 3위로, 실행 시점 강제 표준(ACS)도 함께 나왔다

WHAT

OWASP GenAI Security Project가 2026년 9월 1일 "2026 Top 10 for LLM Applications"를 공개했다. 이번 판이 이전과 다른 점은 방법론이다 — 지금까지는 전문가 커뮤니티의 합의 투표로 순위를 매겼지만, 이번에는 처음으로 실제 프로덕션 인시던트 데이터(수천 건 규모)를 순위 산정에 함께 반영했다. 전체 10개 항목은 LLM01 Prompt Injection, LLM02 Sensitive Info Disclosure, LLM03 Excessive Agency, LLM04 Data and Model Poisoning, LLM05 Improper Supply Chain, LLM06 Insecure Output Handling, LLM07 Vector and Memory Flaws, LLM08 Misinformation, LLM09 Hidden Context Exposure, LLM10 Unbounded Consumption이다. 이 중 LLM03 "Excessive Agency"(과도한 자율성 부여)가 리스트 전체에서 가장 큰 폭으로 순위가 올랐다 — 모델 출력이 검증 없이 자율적으로 셸 명령을 실행하거나 외부 API를 호출하거나 DB 트랜잭션을 처리하는 에이전트형 시스템에서 실제 사고가 집중된 결과다. 동시에 새로운 "Agent Control Standard"(ACS)가 프로젝트에 기증되어 함께 공개됐는데, 이건 또 다른 위험 목록이 아니라 자율 에이전트가 무엇에 접근하고 무엇을 결정하고 무엇을 실행할 수 있는지를 실행 시점(runtime)에 실제로 제약하는 실무 강제 방법에 초점을 맞춘 표준이다. 공개 48시간 만에 1만 다운로드를 돌파했다.

WHY

중요한 이유는 두 가지다. 첫째, Excessive Agency의 순위 상승이 이론적 우려가 아니라 실제 인시던트 데이터로 뒷받침된다 — 업계 전체가 지금 가장 많이 실패하고 있는 지점이 정확히 "모델이 뭔가를 하겠다고 말한 것"과 "그게 실제로 실행되는 것" 사이라는 뜻이다. 둘째, ACS의 존재 자체가 더 의미심장하다 — 지금까지 나온 위험 목록들은 대부분 "이런 위험이 있다"는 분류(taxonomy)에 그쳤지만, ACS는 "그럼 그걸 실제로 어떻게 막는가"라는 강제(enforcement) 층위로 한 단계 내려간 첫 업계 표준이다. 이건 최근 브리프가 다뤄온 사례들 — OpenAI 격리 평가 에이전트의 프로덕션 침투(8/29), Anthropic MHS가 안전 한계를 드라이버 계층에 배치해 반대로 성공한 사례(8/30), "백그라운드 자동 실행"이라는 이유만으로 승인 절차 자체가 아예 없었던 GitSpawn류 사례(9/3) — 를 관통하는 하나의 축(모델의 요청과 실제 실행 사이에 강제 지점이 있는가, 그 지점이 어느 계층에 있는가)에 업계가 이제 공식 이름과 표준을 붙이기 시작했다는 신호다.

FOR YOU

agent_harness_engineering.gaps.tool_calling_runtime_architecture의 잔여 지점 — "모델이 하네스에 보내는 것은 실행이 아니라 구조화된 요청이며, 그 사이에 하네스가 거부·변형·승인을 끼울 수 있다"는 것 — 이 이번 뉴스에서 Excessive Agency라는 정식 이름을 얻었다고 보면 된다. 그 요청이 구조화된 요청 단계에서 멈추지 못하고 검증 없이 그대로 실행으로 이어지는 상태 자체가 Excessive Agency다. system_design_architecture.development_targets.logical_boundary_vs_runtime_boundary에서 아직 못 채운 반대 방향 — "그럼 어디에 강제 지점을 둬야 실제로 막히는가"(저장 위치가 아니라 실행 경로 위/아래 계층의 문제) — 를 ACS가 정면으로 다룬다. 이 도메인의 next_probe로 이미 지정돼 있던 2026-08-30 Anthropic MHS 사례("안전 한계를 드라이버 계층, 즉 실행 직전·하드웨어 바로 위에 둔다")가 지금 와서 보면 ACS가 요구하는 것의 구체적인 선행 사례였던 셈이다 — 그때는 개별 사례였지만 이제는 업계가 표준화하려는 패턴이라는 게 확인됐다. ai_coding_agents.gaps.tool_execution_boundary도 같은 뿌리이므로 함께 갱신 대상.

LEARN

10개 항목 전부를 암기할 필요는 없다 — 용어 나열이 아니라 구조 이해가 목표다. 다만 (1) "Excessive Agency"라는 용어와 정의는 AX 강의에서 에이전트 보안을 설명할 때 그대로 인용할 수 있는 업계 표준 어휘라 익혀둘 가치가 있고, (2) ACS는 방금 기증된 신생 표준이라 구체적 강제 메커니즘(체크리스트, 레벨 등)이 아직 다 공개되지 않았다 — 지금 깊이 팔 단계는 아니며, 향후 브리프에서 ACS의 구체적 내용이 공개되면 그게 logical_boundary_vs_runtime_boundary의 다음 next_probe 앵커가 된다는 것만 표시해두고 넘어가면 된다.

3줄 요약

  1. OWASP GenAI Security Project는 2026년 9월 1일 "2026 Top 10 for LLM Applications"를 발표했으며, 이번 판은 최초로 실제 인시던트 데이터를 커뮤니티 순위 평가에 반영했다.
  2. 순위 변화 중에서는 에이전트형 시스템의 셸 명령 실행, 외부 API 호출, DB 트랜잭션 처리와 관련된 사고가 늘면서 LLM03 "Excessive Agency" 항목이 가장 크게 상승했다.
  3. 전체 순위는 프롬프트 인젝션, 민감정보 노출, 과도한 자율성 부여 등 총 10개 항목으로 구성되며, 이와 함께 자율 에이전트의 접근·결정·실행을 런타임에서 제약하는 "Agent Control Standard"가 새로 공개되었다.

용어 해설

OWASP GenAI Security Project
웹/애플리케이션 보안 분야의 대표적 비영리 커뮤니티인 OWASP가 생성형 AI/LLM 애플리케이션에 특화해 만든 취약점 순위 프로젝트. 기존 웹 보안 표준으로 널리 쓰이던 OWASP Top 10 방법론을 LLM·에이전트 영역으로 확장한 것이다.
Unbounded Consumption (LLM10)
모델 호출 횟수나 처리량에 제한이 없어서, 반복 요청 등으로 비용을 폭증시키거나 서버 자원을 고갈시켜 서비스를 마비시킬 수 있는 취약점.
Agent Control Standard (ACS)
에이전트가 "무엇을 해도 되는지"를 정책 문서로만 적어두는 데 그치지 않고, 그 규칙을 실행되는 순간에 실제로 거부·수정·승인할 수 있는 강제 계층을 어떻게 구현할지 규정하는 새 표준. "모델 출력은 실행이 아니라 요청일 뿐이고 그 사이에 하네스가 개입해야 한다"는 개념을 실무 프레임워크로 표준화한 것에 가깝다.
