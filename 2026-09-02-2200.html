Claude Code Auto Mode의 "격리 탈출 규칙" — 경계를 지키는 게 규칙이 아니라 확률적 분류기라면

WHAT

2026-09-01, Claude Code 2.1.257에서 auto mode(승인 없이 자율 실행하는 모드)에 "Containment Escape rule"이 추가됐다. 클라우드 메타데이터/자격증명 조회, egress evasion(아웃바운드 통제 우회), cross-tenant reach(테넌트 경계를 넘는 접근) 세 카테고리는 이제 환경이 명시적으로 "예상된 동작"이라 표시하지 않는 한 자동 승인되지 않는다.

Anthropic 엔지니어링 블로그가 공개한 내부 동작은 이렇다: 도구 호출은 3단계(Tier)로 걸러진다. Tier 1(파일 읽기 등 안전한 내장 도구)과 Tier 2(프로젝트 내부 파일 편집, 버전관리로 검토 가능)는 분류 자체를 건너뛴다. 나머지 전부 — 셸 명령, 외부 API 호출, 프로젝트 밖 파일 접근 — 가 Tier 3로 가서 실제 분류를 거친다. Tier 3는 다시 2단계다: 1단계는 설명 없이 즉시 yes/no만 내리는 빠른 필터(차단 쪽으로 편향, false positive 8.5%), 2단계는 1단계에서 걸린 것만 chain-of-thought로 재검토해 false positive를 0.4%까지 낮춘다. 분류기는 사용자 메시지와 실제로 실행될 도구 명령만 보고 에이전트 자신의 설명이나 도구 실행 결과는 배제한다 — 모델이 스스로를 설득해 위험한 행동을 승인하는 것을 막고 prompt injection에도 방어가 되는 설계다. 기본 차단 규칙은 20개 이상, 4개 그룹(파괴/유출, 보안 저하, 신뢰 경계 넘기, 리뷰 우회)으로 나뉜다. 그리고 Anthropic은 한계도 공개했다: 실제 위험한 행동에 대한 false negative율이 17%다 — 분류기가 위험 자체는 인식하고도 "이게 사용자 동의 범위 안인가"를 잘못 판단하는 경우가 대부분이라고 설명한다.

WHY

이번 주 내내 "logical boundary(설계상 그렇게 하기로 했다)"와 "runtime boundary(실행 중 실제로 강제된다)"의 차이를 여러 각도에서 봤습니다 — 8/29 OpenAI 격리 실패(경계가 논리적으로만 존재), 8/30 Anthropic MHS(로봇 드라이버 계층에서 실행 전 하드하게 강제, CMU 테스트 6/6 전부 차단). 이번 건은 그 스펙트럼에 세 번째 지점을 추가합니다: 하드코딩된 결정론적 제약이 아니라, AI 분류기가 매 호출마다 확률적으로 판단하는 경계입니다. MHS의 드라이버 계층 제약은 "이 명령은 물리적으로 실행되지 않는다"는 보장이었다면, 이 Containment Escape rule은 "이 행동은 대체로(83% 확률로) 차단된다"는 보장입니다. 둘 다 "경계"라고 부르지만 신뢰 모델이 근본적으로 다릅니다.

FOR YOU

system_design_architecture.development_targets.logical_boundary_vs_runtime_boundary(P1, partial)에 직접 연결됩니다 — 지금까지는 "경계가 설계에만 있는가, 실행 중에도 강제되는가"라는 이분법으로 이 주제를 봤다면, 오늘 건은 그 안에서 한 단계 더 쪼갤 지점을 보여줍니다: 실행 중 강제되는 경계도 결정론적(deterministic) 강제와 확률적(probabilistic) 강제로 나뉜다는 것. 아키텍처 다이어그램에 "여기에 승인 게이트가 있다"고 그렸을 때, 그 게이트가 이 둘 중 무엇인지는 완전히 다른 질문입니다. 특히 decomposition_overconfidence(관찰된 경향 — 경계를 그어두면 그것만으로 안전하다고 과신할 소지)와 정확히 맞물리는 지점입니다: "승인 게이트가 있다"와 "그 게이트가 17% 확률로 뚫린다"는 동시에 참일 수 있고, 후자를 설계 문서에 명시하지 않으면 그 시스템을 나중에 쓰는 사람(팀원이든 미래의 자신이든)은 그 게이트를 실제보다 더 단단한 것으로 오해하게 됩니다. Anthropic 스스로 이 17%라는 숫자를 공개했다는 점도 눈여겨볼 만합니다 — 확률적 경계를 설계할 때는 "막는다"가 아니라 "얼마나 막는가"를 수치로 갖고 있어야 그 경계를 신뢰할 근거가 생깁니다.

LEARN

이번 릴리스의 구체적 규칙 목록(20여 개, 4개 그룹)은 fast_moving(claude_code_features)이라 세부는 곧 바뀔 것이므로 암기할 필요는 없습니다. 하지만 "경계 = 결정론적 제약 vs 확률적 분류기"라는 구분 자체는 agent architecture 설계에서 재사용되는 evolving_practice 수준의 durable한 판단 프레임입니다 — 다음에 직접 Harness에 승인/차단 게이트를 넣을 때 "이건 규칙 기반인가, 판단 기반인가, 후자라면 오탐/누락률을 어떻게 알 것인가"를 먼저 물어보는 습관으로 남을 가치가 있습니다.

3줄 요약

  1. Anthropic이 2026년 9월 1일 Claude Code 2.1.257의 auto mode에 "Containment Escape rule"을 추가해, 사용자 환경이 명시적으로 예상된 동작이라고 표시하지 않는 한 클라우드 메타데이터/자격증명 조회, egress evasion, cross-tenant reach를 자동 승인하지 않도록 했다.
  2. Anthropic 엔지니어링 블로그에 따르면 auto mode는 3단계 파이프라인으로 동작하며, 셸 명령·외부 API 호출·프로젝트 밖 파일 접근을 다루는 Tier 3는 빠른 필터(false positive율 8.5%)와 이를 재검토하는 chain-of-thought 단계(false positive율 0.4%)의 2단계 분류를 거치고, 사용자 메시지와 실제 실행되는 도구 명령만을 근거로 판단하며, 4개 그룹으로 나뉜 20개 이상의 기본 차단 규칙을 적용한다.
  3. 알려진 한계로 실제 과도한 위험 행동에 대한 false negative율이 17%로 측정됐으며, 이는 주로 분류기가 위험 자체는 인식하면서도 해당 행동이 사용자 동의 범위 안에 있는지를 잘못 판단하기 때문이라고 설명된다.

용어 해설

cloud metadata-credential fetches
클라우드 서버 내부에는 그 서버의 API 키 같은 자격증명을 내어주는 특수 내부 주소(메타데이터 엔드포인트)가 있는데, 이를 조회해 자격증명을 빼내려는 시도를 말한다.
egress evasion
egress는 서버에서 외부로 나가는(아웃바운드) 네트워크 트래픽이며, egress evasion은 방화벽 등 아웃바운드 통제를 우회해 데이터를 몰래 밖으로 빼내려는 시도다.
cross-tenant reach
tenant는 하나의 인프라를 함께 쓰는 개별 고객·조직 단위이며, cross-tenant reach는 한 테넌트가 다른 테넌트의 데이터·자원 경계를 넘어 접근하는 것이다.
false positive / false negative rate
false positive는 실제로는 안전한데 위험하다고 잘못 판단해 과잉 차단하는 것, false negative는 실제로 위험한데 안전하다고 잘못 판단해 놓치는 것이다. 본문의 8.5%/0.4%/17%는 각각 이 오판 비율이다.
chain-of-thought
모델이 최종 답을 내기 전에 중간 추론 단계를 텍스트로 풀어서 거치는 방식. 본문에서는 이 추론 과정을 거쳐 1단계 필터의 판단을 다시 검토하는 2단계를 가리킨다.
